## Customer registration requirements

- Required: first name, last name, unique username, email, password, street address, city, state/province, country code, ZIP/postal code.
- Username: 3–30 letters, numbers and underscores, unique ignoring case. **Sign-in uses email, not username.**
- Optional: phone and street unit/suite.
- Billing address can be different or selected as **same as account address**.
- Permanent customer Account ID generated by Postgres in MB-... format. Account ID is a display reference, not an authentication secret.
- Existing Owner account is retained and may complete missing profile fields.
- Customer profiles, billing and delivery details are private under RLS; only their account holder and authorized Owner/Admin can read them.

## CAPTCHA implementation

- Dedicated Cloudflare Turnstile managed widget in the authorized MommaBees account.
- Allowed hostname: mommabees-website.pages.dev.
- Public sitekey in site/config.js; signing secret encrypted in Cloudflare Pages production as TURNSTILE_SECRET_KEY.
- Both sign-in and signup invoke first-party Pages Functions (/api/auth/login and /api/auth/register).
- Pages Functions verify a one-time Turnstile token with Cloudflare Siteverify and compare expected hostname BEFORE forwarding sign-in or signup to Supabase Auth.
- Missing secrets or invalid tokens fail closed.
- **Outstanding security work:** Direct Supabase Auth endpoints are publicly reachable without Supabase native CAPTCHA. Native CAPTCHA cannot verify the same already-redeemed token. A later native Auth CAPTCHA migration must remove proxy verification and enable native verification together, with Owner lockout safeguards.

## Private messages and attachments

- Signed-in customer dashboard contains Account ID, profile editor, notifications, orders, and private message threads.
- Subject selector: Existing order, Custom cake/special order, Pickup/delivery, Products/allergens, Payments/billing, Comments/feedback, Other.
- Selecting Other displays a required custom subject field.
- Customers may write new threads and reply within their own conversations. Owner/Admin may respond and view submitted photos in the same Admin inbox.
- Up to five attached JPG/PNG/WebP images per message, maximum 5 MB each.
- Private Supabase storage bucket: message-photos. Object keys begin with authenticated customer UUID and message UUID. Signed view links expire.
- Database policies limit each conversation to its customer and authorized Owner/Admin. Reply parentage is enforced with a database trigger, and another trigger enforces the five-photo count with row locking.
- Customer/staff replies create in-app notifications. Email and SMS transport are not automatically enabled by this change.
- Guest contact messages are still permitted through the existing guest-contact workflow without private file attachments.
